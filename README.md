# 아마추어 글쓰기 — 밤의 문장들 (v14.23)

## 이번 수정: 공개한 책이 다시 비공개가 되는 원인 해결

**실제 원인:** 이전 버전은 공개된 책을 Render의 `data/room-books.json`에 기록했습니다. Render **무료 Web Service**는 잠자기(spin-down), 재시작, 재배포 시 파일 변경사항이 사라집니다. 서버의 공개 책 목록이 없어지면 브라우저가 이전에 공개된 책을 단순히 '내 비공개 글'로 잘못 분류했습니다.

**바뀐 점**
- **Supabase 영구 데이터베이스**를 지원합니다. 서버가 꺼지거나 재배포돼도 공개 책이 데이터베이스에서 다시 로딩됩니다.
- 실제 데이터베이스 기록이 성공한 경우에만 **영구 공개 완료**로 처리합니다. DB 접속/쓰기 오류가 나면 공개를 거절하고 원인을 안내하며 글쓰기 초안을 유지합니다.
- 공개했지만 지금 서버에서 찾지 못하는 옛 책은 **'⚠️ 공개 기록 확인 필요'**로 별도 표시합니다. **다시 공개하기**로 복구할 수 있습니다. 예전에 공개했던 책을 비공개라고 잘못 안내하지 않습니다.
- 기존 책장 디자인 **표지 제목 60% + `글쓴이 . 이름` 40%, 한 화면 9권**, 본문 **10,000자**, 멤버 공유·수정·삭제·심리방·채팅 기능을 유지합니다.

## 반드시 1회 설정 — Supabase (Render 무료 웹 서비스 이용자)

GitHub에 ZIP만 새로 올리는 것으로는 영구 저장이 되지 않습니다. **Supabase라는 별도 데이터베이스를 한 번 연결해야 합니다.** 설정하지 않으면 기존처럼 **임시 공개**라고 경고가 표시됩니다.

1. [Supabase](https://supabase.com/)에 로그인하고 **New project**로 프로젝트를 만듭니다.
2. 왼쪽 **SQL Editor → New query**로 들어가 `supabase_setup.sql`의 내용을 **전부 복사·붙여넣기**한 뒤 **Run**을 누릅니다.
3. Supabase 프로젝트의 **Settings → API Keys**에서 **Secret key** (`sb_secret_...`)를 복사하고, 프로젝트 **URL** (`https://.....supabase.co`)도 확인합니다. Secret key는 브라우저/채팅/GitHub에 올리면 안 됩니다.
4. **Render Dashboard → 해당 Web Service → Environment → Add Environment Variable**에서 아래 **두 항목을 각각 등록**합니다. 값에는 따옴표를 넣지 않습니다.

   | Key | Value |
   | --- | --- |
   | `SUPABASE_URL` | `https://프로젝트주소.supabase.co` |
   | `SUPABASE_SECRET_KEY` | Supabase `sb_secret_...` 비밀 키 |

5. GitHub 업로드용 ZIP을 해제하고 `server.js`, `public` 폴더, `supabase_setup.sql` 등을 GitHub 저장소 **최상위**에 올린 다음 **Commit changes**를 합니다.
6. Render에서 설정을 저장하고 배포를 완료합니다. 홈페이지 주소 뒤에 `/health`를 붙여 **`"version":"14.23.0"`**, **`"shelfStorage":"supabase"`**가 표시되는지 확인하세요.
7. 같은 모임방에서 책장에 들어가 **`✅ 영구 책장 연결됨`**이라는 안내를 확인합니다. 공개 글 하나를 저장하고, 브라우저를 닫았다 다시 접속해 책이 유지되는지 확인하세요.

**보안:** 반드시 **Secret key**를 Render의 환경 변수로만 등록하세요. GitHub 소스코드, 웹페이지, 사진, 채팅에 비밀 키를 붙여넣으면 안 됩니다. 데이터베이스는 서버만 접근하고, 방문자는 기존 모임방 인터페이스로 공개 글을 읽습니다.

### 대안: Render 유료 서버의 영구 디스크

Render **유료 Web Service**를 이용한다면, 영구 디스크를 `/var/data`에 마운트하고 환경 변수 `BOOKSHELF_DATA_DIR=/var/data`를 설정해도 됩니다. Supabase가 연결되어 있으면 Supabase를 우선 사용합니다. Render 무료 Web Service에서는 영구 디스크 연결이 지원되지 않습니다.

## 예전에 사라진 책을 다시 공개하려면

- **원래 글을 작성했던 기기/브라우저에서**, 같은 모임방 코드로 들어갑니다.
- 책장에서 **'⚠️ 공개 기록 확인 필요'** 구역을 찾습니다.
- 해당 책의 **'↻ 공개 다시 등록'** 버튼을 누르면, 외부 저장소에 새로운 공개 책으로 등록할 수 있습니다.
- 같은 기기의 **내 글 목록**에 원본 초안이 있다면 공개할 글 선택 메뉴에서도 다시 공개할 수 있습니다.
- **기기/브라우저에도 글이 없고 서버 임시 파일도 이미 삭제됐다면** 프로그램만으로 복구할 수 없습니다. 별도 백업 파일이 있어야 합니다.
- 이전 서버의 임시 파일에 아직 책이 남아 있을 경우, 새 DB 연결 직후 서버 내부에 남아 있는 로컬 책장 파일을 **최초 한 번 자동 이전**하려고 시도합니다. Render가 이전 파일을 이미 지웠다면 해당 내용은 이전되지 않습니다.

## 문제가 있으면

- `/health`의 `shelfStorage`가 `"ephemeral"`이면: 영구 저장소 미설정입니다.
- `/health`의 `shelfStorage`가 `"supabase"`이지만 책장에 `서버 책장 확인 실패` 경고가 나오면: Supabase 주소/키/SQL 테이블/프로젝트 상태를 확인합니다. 설정만 됐다고 연결 성공을 의미하지는 않습니다.
- 등록 시 `[원인: STORAGE_FAILED · HTTP 503]`은 DB가 책을 기록하지 못했다는 뜻입니다. 이때 **책이 공개되었다고 표시하지 않습니다**.
- `CHAR_LIMIT`는 **본문이 10,000자를 초과한 경우**입니다.
- Render의 `Logs` 메뉴에서 `책장 초기화 실패` 또는 `책 공개 기록 실패` 문구를 확인할 수 있습니다. 비밀 키 자체는 로그에 기록하지 않습니다.

## 직접 실행하기

Node.js **18 이상**에서 `node server.js` (기본 http://localhost:3000). Supabase 환경 변수를 지정하지 않으면 로컬 `data/room-books.json`에 저장합니다.

외부 DB 연결은 개발 환경에서 **모의 Supabase REST 서버**를 사용해 검증했으며, 실제 사용자 Supabase 프로젝트에는 접근해 검증하지 않았습니다.
