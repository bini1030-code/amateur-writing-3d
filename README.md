# 아마추어 글쓰기 — v14.19 책장 공개 안정화

## 이번 업데이트

- 책장 공개 요청을 **기존 WebSocket 메시지 대신 전용 HTTP `POST /api/shelf/publish`**로 처리합니다. 서버가 HTTP 상태와 사유 코드를 돌려줘 오류를 정확히 구분합니다.
- **본문 최대 10,000자**(한글 및 이모지 포함, 유니코드 코드 포인트 기준), 제목 최대 80자를 화면·서버에서 함께 검증합니다.
- 이전의 **65,000바이트 중복 전송 제한을 256KB**로 상향해 10,000자 글이 별도 바이트 제한에 걸리는 경우를 방지합니다. 본문 글자 수 제한 10,000자는 그대로 엄격히 적용됩니다.
- 공개할 글 선택 메뉴에 **현재 글자 수 / 최대 10,000자**가 표시됩니다.
- HTTP 오류 발생 시 `CHAR_LIMIT`, `EMPTY_TEXT`, `NO_OWNER_KEY`, `SHELF_FULL`, `NOT_OWNER`, `SERVER_ERROR` 등의 실제 사유와 HTTP 상태를 안내합니다. 오류 문구는 밝은 바탕과 진한 빨간색 글자로 표시됩니다.
- 성공한 요청은 방에 접속한 다른 이용자에게 실시간 알림되며, 동일 요청 번호의 재시도로 책이 중복되지 않도록 처리합니다.
- 기존 글쓰기 초안·책장 수정/삭제·여섯 얼굴 심리방·채팅·배경음악 기능을 유지했습니다.

## GitHub 및 Render 업로드

1. `GitHub업로드용.zip`의 압축을 풉니다.
2. 압축을 푼 **`server.js`, `package.json`, `public` 폴더 등을 GitHub 저장소 최상위**에 업로드하고 변경사항을 저장합니다. ZIP 파일 자체나 상위 폴더 하나를 올리는 것이 아닙니다.
3. Render 자동 배포 완료 후 `https://여러분의주소/health`를 엽니다. 다음 내용이 있어야 합니다.

   `"version":"14.19.0"`, `"shelfMaxChars":10000`, `"shelfPublish":"http-v1"`

4. 기존 사이트를 **새로고침**하여 다시 입장한 뒤 책장에 글을 꽂습니다.

## 저장이 또 실패하면

책장 아래 오류 메시지에 **원인 코드와 HTTP 번호**가 표시됩니다.

- `CHAR_LIMIT` (HTTP 422): 본문 10,000자 초과. 현재 글자 수와 줄여야 하는 글자 수가 표시됩니다.
- `EMPTY_TEXT` (HTTP 422): 본문이 비어 있습니다.
- `NO_OWNER_KEY` (HTTP 400): 원래 브라우저의 관리 키를 읽을 수 없습니다. 사이트 데이터 저장 허용 여부 확인.
- `SHELF_FULL` (HTTP 409): 모임방 책 100권에 도달했습니다.
- `HTTP 404`/`METHOD_INVALID`: 클라이언트 파일은 새 버전이나 실제 서버가 구버전입니다. `server.js`와 Render 배포 상태 확인.
- `HTTP 500` 및 `SERVER_ERROR`: 서버 처리 오류. Render 로그 확인.
- `storage:temporary`: 화면상 다른 사람에게 즉시 공유되지만 서버 디스크에 남기지 못했으므로 재시작 후 사라질 수 있습니다.

**중요:** Render 무료 웹서비스의 로컬 파일은 재배포·재시작 이후 보존을 보장하지 않습니다. 영구적인 공동 책장은 별도 데이터베이스 또는 영구 저장 공간이 필요합니다.

## 검증 결과 (로컬 환경)

- 실제 Node 서버 `POST /api/shelf/publish`: 짧은 글, 한글 5,000자, 한글 10,000자, 이모지 10,000자, 이스케이프 문자가 포함된 본문 저장 성공.
- 10,001자 요청: HTTP 422 `CHAR_LIMIT` 및 초과 글자 수 반환.
- 같은 모임방의 서로 다른 두 WebSocket 이용자에게 새 책 알림이 모두 전달됨.
- 동일 요청 ID 재전송 시 중복 등록 없음.
- 테스트용 저장 디렉터리에 저장 후 서버 재시작 시 5권 복원됨.
- 브라우저 모의 통신 테스트: 10,000자 공개 완료와 표지 반영, 10,001자 사전 차단, HTTP 503 상세 오류 안내 확인.
- 실제 Render 배포 주소 또는 실사용 기기에서의 테스트는 수행하지 못했습니다.
