# 아마추어 글쓰기 — 밤의 문장들 (v14.26)

## 이번 업데이트 — 강아지 산이 · 고양이 보리 · 아기 고양이 햇살이

**실제 3D 공간에 세 마리의 반려동물 NPC**를 추가했습니다. 단순 사진·스티커가 아니라 WebGL에서 회전하고 움직이는 입체 모델이며, WebGL을 사용할 수 없는 기기는 기존 소프트웨어 3D 렌더러로 표시합니다.

- **산이(강아지):** 소형견, 흰 몸과 베이지색 귀. 가끔 뛰어다니며 앉고 눕고 꼬리를 흔듭니다. 부르면 플레이어 가까이 달려오고 폴짝 반응합니다.
- **보리(고양이):** 사용자가 제공한 사진을 참고한 주황색·흰색 무늬의 성묘. **사진 속 노란 목베개는 포함하지 않았습니다.** 조용히 걷고 앉거나 눕고 하품·기지개·몸 비비기 동작을 합니다.
- **햇살이(아기 고양이):** 보리와 비슷한 주황색·흰색 무늬지만 체구가 약 72%인 아기 고양이. 빠르게 뛰다가 장난감에 반응합니다.
- **자유 배회:** 서버가 길 찾기를 계산하므로 실내에서 정해진 한 곳에만 머무르지 않습니다. 출입구와 방의 바닥을 이용하면서 책상·의자·벽을 피해 이동합니다. 동물 세 마리의 위치와 행동은 **같은 모임방 코드에 접속한 모든 참가자에게 동일하게** 전달됩니다.

### 동물에게 상호작용하기

1. 모임방에 접속해서 동물 가까이 이동합니다. 이름표와 함께 **동물 머리 위에 🐾 / 🍪 / 👋 아이콘**이 나타납니다.
2. 아이콘을 직접 누르면 다음 행동을 바로 실행합니다.
   - `🐾 쓰다듬기`: 산이는 꼬리를 흔들고, 고양이들은 몸을 비빕니다.
   - `🍪 간식 주기`: 동물이 앉아 간식을 먹는 동작을 합니다.
   - `👋 부르기`: 산이는 빠르게, 보리·햇살이는 천천히 플레이어 쪽으로 다가옵니다.
3. **`E` 키** 또는 모바일 상호작용 버튼을 누르면 동물 놀이 메뉴가 열립니다. 거기서 `🎾 공놀이`(산이)나 `🧶 장난감 흔들기`(고양이)를 선택할 수 있습니다. 작은 3D 공/털실과 놀이 반응이 나타납니다.
4. 한 사람이 쓰다듬거나 부르면 **다른 사람 화면에도 동일한 반응 아이콘과 행동이 보입니다.** 가까이 가지 않거나 연결이 끊기면 동물 상호작용을 요청할 수 없습니다.

### 설치와 기존 영구 책장

- `server.js`, **새 파일 `pets-server.js`**, `public/`, `package.json` 등을 GitHub 저장소 **최상위**에 올리고 커밋하세요. `public/` 폴더만 올리면 동물 동기화가 되지 않습니다.
- Render 배포 후 사이트 주소 뒤에 `/health`를 붙여 `"version":"14.26.0"`이 표시되는지 확인하세요.
- **기존 Supabase `SUPABASE_URL`과 `SUPABASE_SECRET_KEY`를 다시 설정할 필요 없습니다.** DB 테이블도 변경하지 않았으며 글 공개·영구 보존 방식은 이전과 동일합니다.
- 동물은 서버 메모리에서 움직이므로 서버가 완전히 재시작하면 세 마리가 처음 위치에서 다시 자유 배회를 시작합니다. **책 데이터는 동물 위치와 관계없이 기존 Supabase에 유지됩니다.**

### 이번 업데이트 검증

- 서로 다른 참가자 **2명**을 실제 WebSocket 서버에 접속시켜 세 마리 표시와 행동 전송(쓰다듬기·간식·부르기·놀이)을 검사했습니다.
- 실제 HTTP 서버에서 한글 **10,000자 공개** 및 다른 참가자에게 책 전달을 다시 확인했습니다.
- 3D 동물 메시를 기존 3D 엔진으로 렌더링하고, PC·모바일 UI의 머리 위 이름/아이콘/놀이 메뉴를 검사했습니다. 자동 브라우저는 **WebGL 비활성화 환경**이라 소프트웨어 3D 모드로 검사했습니다. 실제 Render 배포 사이트에서의 그래픽 성능은 별도 확인이 필요합니다.
- 동물 이동은 다양한 경로로 반복 검사했으며 가구 통과를 방지하기 위한 경로 계산을 보완했습니다.

## 이전 버전 기능 — 글쓴이별 책장 + 페이지 없는 연속 스크롤

- **공개 책장을 글쓴이별 구역으로 분리했습니다.** 예: `전민재 님의 책 (3권)`, `김하늘 님의 책 (2권)`. 작성자 이름의 가나다순으로 나열하고 구역마다 서로 다른 테두리와 아이콘으로 구분합니다.
- **글쓴이 선택 메뉴**에서 모든 글쓴이 또는 특정 글쓴이 한 명의 작품만 표시할 수 있습니다. 제목·작성자 검색도 그대로 작동합니다.
- **책장에 꽂힌 책을 누르면 본문 전체가 한 번에 펼쳐집니다.** 예전의 300자 단위 페이지 나누기와 이전/다음 버튼을 제거하고 책을 위에서 아래로 쭉 스크롤하여 읽습니다. 장문 10,000자도 끊기지 않습니다.
- 기존 **책 표지 60%(제목) : 40%(글쓴이 . 이름)** 구성, PC/모바일 3열, 글 수정·삭제, 비공개 글, 10,000자 공개, Supabase 영구 저장 기능을 유지합니다.
- **두 공간의 책장은 같은 목록을 사용합니다.** 글쓰기 모임방과 여섯 얼굴의 방에 동일하게 적용됩니다.
- 다른 참가자가 볼 수 있는 책은 공개한 작품뿐입니다. **비공개 초안은 자기 기기에만 남고 글쓴이별 공개 목록에는 포함되지 않습니다.**

**적용 순서:** ZIP을 푼 뒤 `server.js`, `public/`, `package.json` 등을 GitHub 저장소 **최상위**에 덮어쓰고 Commit changes를 선택합니다. Render 자동 배포가 끝나면 `/health`에서 `"version":"14.26.0"`을 확인합니다. 이미 Supabase 환경 변수를 설정했다면 새로 입력할 필요가 없습니다.

### 확인한 사항
- v14.24 당시 서버에서 서로 다른 작성자 3명의 책 9권을 HTTP 공개했습니다.
- PC(1280×850), 모바일(390×844), 작은 모바일(320×568)의 브라우저 UI에서 글쓴이별 구역·글쓴이 선택·책 열기·본문 연속 스크롤·책장 돌아가기를 확인했습니다. 브라우저 검증은 실제 프로젝트의 책장 렌더링 함수를 별도 화면에 연결해 테스트했으며, 전체 3D 공간을 다시 실행한 것은 아닙니다.
- 장문 9,556자를 마지막 문장까지 확인했고, 책 저장 서버와 데이터베이스 처리 코드는 버전 문자열 외에 변경하지 않았습니다.

## v14.23부터 제공되는 기능: 공개한 책이 다시 비공개가 되는 원인 해결

**실제 원인:** 이전 버전은 공개된 책을 Render의 `data/room-books.json`에 기록했습니다. Render **무료 Web Service**는 잠자기(spin-down), 재시작, 재배포 시 파일 변경사항이 사라집니다. 서버의 공개 책 목록이 없어지면 브라우저가 이전에 공개된 책을 단순히 '내 비공개 글'로 잘못 분류했습니다.

**바뀐 점**
- **Supabase 영구 데이터베이스**를 지원합니다. 서버가 꺼지거나 재배포돼도 공개 책이 데이터베이스에서 다시 로딩됩니다.
- 실제 데이터베이스 기록이 성공한 경우에만 **영구 공개 완료**로 처리합니다. DB 접속/쓰기 오류가 나면 공개를 거절하고 원인을 안내하며 글쓰기 초안을 유지합니다.
- 공개했지만 지금 서버에서 찾지 못하는 옛 책은 **'⚠️ 공개 기록 확인 필요'**로 별도 표시합니다. **다시 공개하기**로 복구할 수 있습니다. 예전에 공개했던 책을 비공개라고 잘못 안내하지 않습니다.
- 기존 책장 디자인 **표지 제목 60% + `글쓴이 . 이름` 40%, 한 화면 9권**, 본문 **10,000자**, 멤버 공유·수정·삭제·심리방·채팅 기능을 유지합니다.

## 반드시 1회 설정 — Supabase (Render 무료 웹 서비스 이용자)

GitHub에 ZIP만 새로 올리는 것으로는 영구 저장이 되지 않습니다. **Supabase라는 별도 데이터베이스를 한 번 연결해야 합니다.** 설정하지 않으면 기존처럼 **임시 공개**라고 경고가 표시됩니다.

1. [Supabase](https://supabase.com/)에 로그인하고 **New project**로 프로젝트를 만듭니다.
2. 왼쪽 **SQL Editor → New query**로 들어가 `supabase_setup.sql`의 내용을 **전부 복사·붙여넣기**한 뒤 **Run**을 누릅니다.
3. Supabase 프로젝트의 **Settings → API Keys**에서 **Secret key** (`sb_secret_...`)를 복사하고, 프로젝트 **URL** (`https://.....supabase.co`)도 확인합니다. Secret key는 브라우저/채팅/GitHub에 올리면 안 됩니다.
4. **Render Dashboard → 해당 Web Service → Environment → Add Environment Variable**에서 아래 **두 항목을 각각 등록**합니다. 값에는 따옴표를 넣지 않습니다.

   | Key | Value |
   | --- | --- |
   | `SUPABASE_URL` | `https://프로젝트주소.supabase.co` |
   | `SUPABASE_SECRET_KEY` | Supabase `sb_secret_...` 비밀 키 |

5. GitHub 업로드용 ZIP을 해제하고 `server.js`, `public` 폴더, `supabase_setup.sql` 등을 GitHub 저장소 **최상위**에 올린 다음 **Commit changes**를 합니다.
6. Render에서 설정을 저장하고 배포를 완료합니다. 홈페이지 주소 뒤에 `/health`를 붙여 **`"version":"14.26.0"`**, **`"shelfStorage":"supabase"`**가 표시되는지 확인하세요.
7. 같은 모임방에서 책장에 들어가 **`✅ 영구 책장 연결됨`**이라는 안내를 확인합니다. 공개 글 하나를 저장하고, 브라우저를 닫았다 다시 접속해 책이 유지되는지 확인하세요.

**보안:** 반드시 **Secret key**를 Render의 환경 변수로만 등록하세요. GitHub 소스코드, 웹페이지, 사진, 채팅에 비밀 키를 붙여넣으면 안 됩니다. 데이터베이스는 서버만 접근하고, 방문자는 기존 모임방 인터페이스로 공개 글을 읽습니다.

### 대안: Render 유료 서버의 영구 디스크

Render **유료 Web Service**를 이용한다면, 영구 디스크를 `/var/data`에 마운트하고 환경 변수 `BOOKSHELF_DATA_DIR=/var/data`를 설정해도 됩니다. Supabase가 연결되어 있으면 Supabase를 우선 사용합니다. Render 무료 Web Service에서는 영구 디스크 연결이 지원되지 않습니다.

## 예전에 사라진 책을 다시 공개하려면

- **원래 글을 작성했던 기기/브라우저에서**, 같은 모임방 코드로 들어갑니다.
- 책장에서 **'⚠️ 공개 기록 확인 필요'** 구역을 찾습니다.
- 해당 책의 **'↻ 공개 다시 등록'** 버튼을 누르면, 외부 저장소에 새로운 공개 책으로 등록할 수 있습니다.
- 같은 기기의 **내 글 목록**에 원본 초안이 있다면 공개할 글 선택 메뉴에서도 다시 공개할 수 있습니다.
- **기기/브라우저에도 글이 없고 서버 임시 파일도 이미 삭제됐다면** 프로그램만으로 복구할 수 없습니다. 별도 백업 파일이 있어야 합니다.
- 이전 서버의 임시 파일에 아직 책이 남아 있을 경우, 새 DB 연결 직후 서버 내부에 남아 있는 로컬 책장 파일을 **최초 한 번 자동 이전**하려고 시도합니다. Render가 이전 파일을 이미 지웠다면 해당 내용은 이전되지 않습니다.

## 문제가 있으면

- `/health`의 `shelfStorage`가 `"ephemeral"`이면: 영구 저장소 미설정입니다.
- `/health`의 `shelfStorage`가 `"supabase"`이지만 책장에 `서버 책장 확인 실패` 경고가 나오면: Supabase 주소/키/SQL 테이블/프로젝트 상태를 확인합니다. 설정만 됐다고 연결 성공을 의미하지는 않습니다.
- 등록 시 `[원인: STORAGE_FAILED · HTTP 503]`은 DB가 책을 기록하지 못했다는 뜻입니다. 이때 **책이 공개되었다고 표시하지 않습니다**.
- `CHAR_LIMIT`는 **본문이 10,000자를 초과한 경우**입니다.
- Render의 `Logs` 메뉴에서 `책장 초기화 실패` 또는 `책 공개 기록 실패` 문구를 확인할 수 있습니다. 비밀 키 자체는 로그에 기록하지 않습니다.

## 직접 실행하기

Node.js **18 이상**에서 `node server.js` (기본 http://localhost:3000). Supabase 환경 변수를 지정하지 않으면 로컬 `data/room-books.json`에 저장합니다.

외부 DB 연결은 개발 환경에서 **모의 Supabase REST 서버**를 사용해 검증했으며, 실제 사용자 Supabase 프로젝트에는 접근해 검증하지 않았습니다.
