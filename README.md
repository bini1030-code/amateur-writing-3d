# 아마추어 글쓰기 — v14.16 책장 관리·공유 점검 및 머리 위 반응 아이콘

## 변경 사항

- **여러 글 쓰기**: 글쓰기 화면 위에 **내 글 목록**을 추가했습니다. `＋ 새 글 쓰기`로 서로 다른 초안을 만들고, 목록에서 과거 글을 골라 이어 쓸 수 있습니다. 기기당 최대 80편의 초안을 보관합니다.
- **기존 글 이전**: v14.12 이하에서 작성한 단일 글은 업데이트 후 처음 실행할 때 첫 번째 초안으로 가져옵니다.
- **여러 책 꽂기**: 서로 다른 초안을 책장에 공개하면 각각 독립된 책이 됩니다. 같은 초안을 다시 공개하면 책을 중복 생성하지 않고 해당 책의 내용을 갱신합니다. 모임방당 최대 100권.
- **한글 본문 최대 10,000자**: 기존의 작은 WebSocket 전송 제한 때문에 한글 10,000자에 가까운 글이 실패하던 문제를 수정했습니다. 한글 5,000자와 10,000자 저장을 테스트했습니다.
- **명확한 저장 실패 안내**: 글자 수, 제목 길이, 전송 용량, 책장 권수, 연결 오류, 서버 디스크 오류 등을 구분해 메시지로 알립니다. 10,001자를 등록하려 하면 '최대 10,000자, 현재 10,001자, 1자를 줄여 주세요'라고 표시합니다. 에러는 닫혀 있는 화면에 숨기지 않고 팝업을 열어 보여줍니다.
- **기존 기능 보존**: 8인 심리 모임방, 여섯 얼굴의 이야기, 원형 테이블, 배경음악, 다과·식물·조명 효과, 채팅과 함께 읽기 기능을 유지했습니다.

## 설치

1. GitHub용 ZIP을 **압축 해제**합니다.
2. ZIP의 내용물 (`server.js`, `package.json`, `public` 폴더 등)을 **저장소 최상위**에 올립니다. ZIP 자체를 올리지 마세요.
3. `Commit changes` 후 Render 자동 배포가 완료되면 사이트 주소 + `/health`에서 `"version":"14.13.0"`을 확인합니다.

## 저장 방식과 유의사항

- 글 초안은 **사용 중인 브라우저의 로컬 저장소**에 보관됩니다. 같은 기기/브라우저에서 다시 들어오면 목록이 유지되지만, 브라우저 저장 데이터를 지우거나 다른 기기로 바꾸면 초안을 확인할 수 없습니다. 중요한 작품은 `↓ 나의 글 저장`으로 별도 백업하세요.
- 서가에 꽂은 글은 같은 모임방 참가자에게 공개되며, 기본적으로 `data/room-books.json`에 서버 저장됩니다. **Render 무료 인스턴스의 디스크는 재배포·재시작 후 유지되지 않을 수 있습니다**. 여러 기기에서 영구 보관하려면 영구 디스크 또는 데이터베이스가 필요합니다.
- 저장 응답이 `임시 공유`라고 표시되면 서버 디스크 저장에 실패했다는 뜻입니다. 서버 재시작 후 공유 목록에서 사라질 수 있습니다.
- 저장 중 오류가 나더라도 기기에서 작성 중인 초안은 자동으로 삭제되지 않습니다.

## 점검

- `node --check server.js`, `node --check public/game.js`
- 로컬 WebSocket 테스트: 한글 5,000자/10,000자, 10,001자 한도 오류, 서로 다른 책 추가, 같은 초안 재발행 후 책 갱신, 다른 참가자 접속, 서버 재시작 후 책 파일 복원
- 브라우저 파일 직접 실행이 제한된 검사 환경에서는 인라인 페이지+가상 서버 응답으로 초안 추가·선택·책장 저장 및 오류 팝업 동작을 검증했습니다. 실제 Render/스마트폰에서의 마지막 검증은 필요합니다.


## v14.14 — 두 모임방 공통 책장 표지 인터페이스

- 책장을 열면 여러 작품이 표지 형태의 그리드로 나타납니다. 제목과 **작성자**를 표지와 아래 안내에 명시합니다.
- 제목/작성자로 검색하고 표지를 클릭하면 책이 펼쳐져 글을 페이지별로 읽을 수 있습니다.
- 뒤로 가기 버튼 또는 Esc를 누르면 전체 책장으로 돌아갑니다.
- 글쓰기 모임방과 심리 모임방의 책장은 같은 모임 코드의 동일한 목록입니다.
- 기존 다중 초안, 여러 권 책장 등록, 1만 자 제한, 저장 성공·실패 메시지 기능은 변경하지 않았습니다.
- Render의 기본 휘발성 저장소에 대한 영구 보존 제약도 기존과 같습니다.

## v14.15 — 책장 속 내 책 수정·삭제

- 글쓰기 모임방 또는 심리 모임방 **책장 → 책 표지 선택** → 본인이 등록한 책에는 `✏️ 책 수정`, `🗑️ 책 삭제`가 나타납니다.
- **책 수정:** 책 제목(최대 80자)과 본문(최대 10,000자)을 고쳐 서버에 저장합니다. 같은 방의 다른 사람 책장에서도 변경된 내용이 보입니다. 원본 초안은 별도로 유지됩니다.
- **책 삭제:** 제목을 확인한 후 삭제합니다. 두 책장의 목록과 참가자 화면에서 제거되며, 삭제 사실을 파일에 기록해 이전 브라우저 캐시 때문에 다시 나타나는 문제를 방지합니다. **삭제는 되돌릴 수 없지만, 브라우저에 남은 글쓰기 초안은 삭제되지 않습니다.**
- **다른 사람의 책:** 읽기는 가능하지만 수정·삭제 버튼은 표시되지 않습니다.
- **관리 권한:** 이 업데이트로 새로 꽂는 책에는 브라우저에 생성하는 무작위 관리 키가 연결됩니다. 같은 이름으로 재입장한 다른 기기는 이 키가 없으므로 수정·삭제할 수 없습니다. **브라우저 사이트 데이터를 지우면 관리 키도 사라지므로 중요한 책을 관리하지 못할 수 있습니다.** 이 프로그램은 회원 가입/본인 인증 시스템을 갖춘 서비스가 아닙니다.
- **이전 버전에서 꽂은 책:** 관리 키가 없으므로 **등록했을 때 사용한 이름과 원본 초안 ID가 해당 브라우저에 남아 있는 경우**에만 이전 방식의 제한적 권한 확인으로 관리합니다. 이 확인은 강력한 본인 인증이 아니므로 원본 초안을 보유한 기기에서 기존 책을 한 번 수정해 관리 키로 전환하는 것을 권합니다. 원본 초안이 없거나 이름이 바뀐 책의 권한은 자동 복구되지 않습니다.
- 글자 수 초과, 저장 권한 오류, 서버 파일 저장 실패, 다른 곳에서 이미 바뀐 글의 충돌 등을 원인별로 화면에 표시합니다.
- 현재 서버 파일 저장소는 Render 무료 환경의 배포/재시작 시 사라질 수 있습니다. 장기 영구 보관에는 데이터베이스나 영구 디스크가 필요합니다.

### 설치 확인

GitHub 업로드용 ZIP을 풀고 `server.js`, `package.json`, `public` 폴더 등을 **저장소 최상위**에 올려 기존 파일을 갱신하세요. Render 배포 후 `/health`에서 `"version":"14.15.0"`을 확인해 주세요.

### 검증

- `node --check server.js`, `node --check public/game.js`
- 실제 Node WebSocket 서버에서 5,000자 등록, 10,000자 수정, 10,001자 초과 오류, 동일 이름 다른 브라우저의 수정/삭제 거절, 두 참가자 간 실시간 반영, 삭제 후 재접속/재시작 유지, 기존 책의 관리 키 전환 검사 통과
- 브라우저의 인라인 UI + 서버 응답 모의 테스트에서 내 책 수정·삭제 버튼, 제목/본문 편집, 다른 멤버 글 읽기 전용, 삭제 후 목록 반영 및 JavaScript 콘솔 오류 없음 확인
- 환경 제약상 실제 Render/모바일 기기의 최종 테스트는 별도로 필요합니다.


## v14.16 — 책 수정·삭제 권한 개선 / 마음 전하기 아이콘 / 공유 확인

### 무엇을 고쳤나요?

- 책의 작성자 이름이 현재 닉네임과 같아도 관리 키가 달라 수정·삭제 버튼이 사라지던 경우를 더 명확하게 처리합니다. 해당 책을 펼치면 **수정·삭제 버튼과 관리 권한 진단 메시지**를 함께 표시합니다. 관리 키를 확인할 수 없는 경우에는 왜 안 되는지와 원래 등록한 브라우저를 사용하는 방법을 안내합니다.
- 같은 브라우저에 예전 닉네임으로 저장된 관리 키가 남아 있으면 이 키들을 확인해 책 권한을 연결합니다. 서버에서는 **관리 키 자체가 맞는 경우** 책을 수정·삭제할 수 있게 해, 같은 사람이 닉네임을 바꿔도 책을 계속 관리할 수 있습니다.
- **관리 키가 없는 이전 버전 책**은 등록 당시의 원본 초안 ID가 같은 브라우저에 남아 있을 때에만 제한적으로 관리 가능합니다. 이 키나 초안이 둘 다 없다면 현재 프로그램에는 본인 확인을 할 수 있는 방법이 없어 기존 책을 안전하게 수정·삭제할 수 없습니다. 다른 사람의 책을 닉네임만으로 삭제하게 만들지는 않았습니다.
- 목록에 **전체 책 수와 현재 서버가 공유 중인 책 수**를 분리해 표시합니다. 다른 사람이 쓴 책의 오래된 브라우저 캐시가 공유 중인 책으로 오인되지 않도록 정리했습니다.
- ‘함께 → 마음을 전하기’에서 💗 마음, 👏 박수, ✨ 반짝임, 👋 인사, ☕ 차 한 잔 등을 누르면 **해당 캐릭터의 머리 위**에 아이콘이 약 1.7초 동안 나타났다 사라집니다. 다른 참가자의 화면에도 전달됩니다. 기존의 부드러운 광원 효과는 유지합니다.

### 다른 참가자도 책을 볼 수 있나요?

**예. 같은 모임방 코드에 접속하고 서버가 보유 중인 책은 모든 참가자가 볼 수 있습니다.** 글쓰기 모임방과 심리 모임방의 책장은 같은 목록을 사용합니다. 별도의 기기에 접속한 참가자에게 책 등록·수정·삭제가 실시간 전달되고, 재접속 시 서버의 책 목록이 제공됩니다. 서로 다른 모임방 코드 간에는 공유되지 않습니다.

다만 Render 무료 인스턴스의 기본 디스크는 **휘발성**입니다. 서버 재배포/재시작 후 모든 사람에게 책이 항상 남게 하려면 영구 저장소(DB 또는 디스크)가 별도로 필요합니다. 현재 브라우저에만 남은 책에는 '이 기기에만 보관'이라고 표시합니다.

### 설치 / 버전 확인

1. GitHub 업로드용 ZIP을 **압축 해제**합니다.
2. ZIP에 들어 있는 `server.js`, `package.json`, `public` 폴더를 **기존 저장소 최상위**에 올리고 `Commit changes`를 누릅니다.
3. Render 배포 후 사이트 주소의 `/health` 경로에서 `"version":"14.16.0"`을 확인합니다. **server.js까지 함께 바뀌지 않으면 책 관리 버튼이 제한됩니다.**
4. 반드시 원래 책을 등록했던 브라우저와 모임방 코드로 먼저 확인하세요.

### 테스트

- 실제 로컬 WebSocket 서버 두 명 접속: 첫 참가자 책 등록 → 두 번째 참가자 수신 → 수정 결과 동기화 → 삭제 결과 동기화 → 늦게 접속한 참가자의 책 목록 확인 통과.
- 같은 이름의 다른 브라우저에서 타인 책 수정·삭제 거부 확인. 같은 관리 키를 보유한 브라우저가 닉네임을 변경해도 수정 가능 확인. 한 브라우저에 보관된 이전·현재 관리 키를 이용해 원래 책 수정 가능 확인.
- 브라우저 내 3D 화면: 수정 버튼·편집창 동작, 관리 키 불일치 안내, 캐릭터 머리 위 반응 아이콘 표시·사라짐 및 타인 박수 아이콘 처리 확인.
- 실제 Render 배포 주소 및 사용자 기기에서의 최종 동작은 별도로 확인해야 합니다.
