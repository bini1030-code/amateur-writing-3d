# 아마추어 글쓰기 — v14.18 책 공개 오류 수정

## 수정 내용

- **책장에서 선택한 비공개 글을 정확히 공개**: 기존 v14.17에서는 책장에 여러 비공개 글이 있더라도 하단의 `내 글 책장에 꽂기` 버튼이 *글쓰기 탭의 현재 활성 초안*을 전송했습니다. 이 버그를 수정했습니다.
- **공개할 글 선택**: 책장 하단의 드롭다운에서 공개할 글을 고르고 `선택한 글 책장에 꽂기 · 즉시 공개`를 누릅니다. 별도의 확인 팝업은 없습니다.
- **비공개 책 표지마다 `📚 이 글 바로 공개` 버튼**: 선택한 책의 제목·본문·초안 ID만 전송합니다.
- **비공개 글 상세 화면의 `이 글 바로 공개하기`** 역시 해당 글을 공개합니다.
- **서버 버전 불일치 안내**: 서버에 책장 저장 확인 기능이 없으면 원인과 배포 방법을 오류 메시지로 알려줍니다.
- 책 공개 시 옛 기기 캐시에 남은 같은 글의 중복 표지를 정리합니다.
- 오래된 HTTP / 비보안 브라우저에서 `crypto.randomUUID`가 없어도 보안 난수 생성 API가 있으면 관리 키를 만들 수 있게 했습니다.

## 사용법

1. 기존처럼 모임방에 입장합니다.
2. 글쓰기 모임방이나 심리 모임방의 책장으로 이동해 책장을 엽니다.
3. **내 비공개 글**의 책 표지에 붙은 **`📚 이 글 바로 공개`**를 누르거나, 아래 **공개할 글 선택** 메뉴에서 제목을 고릅니다.
4. **`선택한 글 책장에 꽂기 · 즉시 공개`**를 한 번 누릅니다.
5. `서버에 저장 중` 표시 뒤에 **책장에 저장했습니다**라는 성공 안내가 나오면, 같은 모임방에 접속한 다른 회원도 그 책을 볼 수 있습니다.

본문은 최대 10,000자, 제목은 최대 80자, 모임방당 최대 100권입니다. 화면과 서버에서 글자 수·전송 오류를 확인합니다. 저장 실패 시 개인 초안은 지워지지 않습니다.

## GitHub → Render 배포

`GitHub업로드용.zip`을 **압축 해제**한 다음, ZIP 안에 바로 보이는 `server.js`, `package.json`, `render.yaml`, `public/` 폴더 등의 내용물을 **GitHub 저장소의 최상위**에 덮어쓴 후 Commit changes 합니다. ZIP 파일 자체를 올리면 작동하지 않습니다.

Render 배포가 끝난 뒤 `https://여러분의주소/health`에 접속하여 `"version":"14.18.0"`이 보이는지 확인하세요. 이전 버전이 보이면 Render 자동 배포가 완료되지 않았거나 GitHub 위치가 잘못된 것입니다. 수정 후에도 구버전이 보일 수 있으니 페이지를 새로고침합니다.

## 보존과 권한 관련 주의

- **비공개 글**은 이 기기의 브라우저 저장 공간에만 남으며 자동으로 다른 회원에게 공유되지 않습니다.
- **공개된 글**은 방 코드별로 같은 모임원들에게 공유됩니다. 다만 무료 Render의 서버 파일 저장 공간은 재배포·재시작 시 초기화될 수 있어 영구 보존을 보장하지 않습니다. 장기 보존에는 외부 DB 또는 영구 디스크가 필요합니다.
- 등록한 책의 수정/삭제는 해당 브라우저의 관리 키로 보호됩니다. 등록했던 브라우저의 사이트 데이터를 삭제하면 관리 권한을 잃을 수 있습니다.

## 점검

- 브라우저 단독 테스트: 서로 다른 비공개 초안 2편을 만들고 두 번째 글을 공개할 때 정확한 제목·본문·초안 ID가 요청에 실리는 것, 다른 비공개 글의 표지에서 직접 공개할 때 그 글만 전송되는 것, 저장 ACK 뒤 표지가 공개 목록에 표시되는 것 확인.
- 실제 Node WebSocket 서버 테스트: 한 작성자가 한글로 된 글을 등록할 때 저장 ACK가 오고, 다른 참가자에게 같은 책이 전송되는 것, 나중에 접속한 참가자의 목록에도 같은 책이 나타나는 것 확인.
- 실제 Render 서비스 및 기기별 WebGL 화면 테스트는 하지 못했습니다.
