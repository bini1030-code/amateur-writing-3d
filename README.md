# 아마추어 글쓰기 — 밤의 문장들 v14.28

## v14.28 — 글쓰기 방을 감싸는 우주 별빛 배경

- 글쓰기 모임방의 큰 짙은 남색 빈 공간에 **별 수천 개와 은은한 보랏빛 성운**이 있는 밤하늘을 렌더링합니다. 별 이미지를 외부 서버에서 가져오지 않고 브라우저에서 직접 생성합니다.
- 카메라를 돌리면 배경이 살짝 달라지는 **WebGL 별빛 배경**을 렌더링합니다. WebGL을 사용할 수 없는 브라우저에서도 **대체 3D 렌더러**로 밤하늘이 보입니다.
- 글쓰기 방 오른쪽의 **세 창문 안쪽에도 별이 보이는 창문 표면**을 입혔습니다. 창틀·책상·화분·아바타 등 3D 물체는 그대로 유지합니다.
- 기존 책 공개/수정/삭제, 글쓴이별 책장, 댓글/방명록, 동물 세 마리, Supabase 영구 저장 **서버 로직과 설정은 변경하지 않았습니다.**
- JS/CSS 파일에 배포 버전 쿼리를 붙여 변경 전 화면 파일이 캐시에서 다시 뜨는 문제를 줄였습니다.

**적용:** GitHub 업로드용 ZIP을 풀면 `server.js`, `pets-server.js`, `public/`, `package.json`, `supabase_setup.sql`이 바로 보입니다. 이 파일들을 GitHub 저장소 최상위에 업로드하고 Render 배포가 완료되면 `https://본인주소/health`에서 `"version":"14.28.0"`을 확인하세요. 기존 Supabase 환경 변수는 다시 입력할 필요가 없습니다.

**테스트:** Node.js 문법 검사 및 HTTP 서버 `/health` 점검, PC/모바일 대체 3D 렌더러 화면 검사(자바스크립트 오류 없음). 현재 테스트 브라우저에서는 WebGL이 차단되어 WebGL GPU 경로의 실제 화면 캡처는 수행하지 못했습니다. ZIP 파일은 루트 폴더 구조를 검증했습니다.

## 새로 추가된 기능

### 📌 글쓰기 방의 3D 방명록 보드

- **글쓰기 방 왼쪽 벽**에 코르크 게시판을 설치했습니다. 가까이 가서 `E` 또는 모바일 `상호작용`을 누르면 방명록을 엽니다.
- 더 쉽게 이용할 수 있도록 화면 왼쪽 공간 이동 메뉴에 **📌 방명록 보드** 바로가기 버튼도 추가했습니다.
- 방명록 글: **최대 500자**. 닉네임과 작성 시각이 함께 표시됩니다.
- 같은 모임방 코드의 모든 참가자가 새 글을 즉시 확인할 수 있습니다.
- 각 방명록 글 아래 **댓글 보기/쓰기**를 누르면 해당 글에 댓글을 달 수 있습니다.

### 💬 공개된 책의 댓글

- 책 표지를 누르고 본문을 아래로 스크롤하면 **이 책에 남긴 이야기** 구역이 나옵니다.
- 다른 사람의 책에도 댓글을 작성할 수 있습니다. 댓글에는 작성자 닉네임과 작성 시각이 표시됩니다.
- **비공개 초안은 댓글 대상이 아닙니다.** 책을 공개한 뒤 댓글을 달 수 있습니다.
- 댓글 하나는 최대 **400자**, 방명록 게시글과 공개된 책 각각 **최대 40개** 댓글을 보관합니다.

## 데이터 저장과 기존 사용자의 Supabase 설정

새로운 SQL 테이블을 추가하지 않습니다. 이미 만들어 둔 Supabase `public.writing_room_shelves` 테이블의 `state` JSONB 내부에 기존 `books`, `deleted`와 함께 `guestbook`, `comments`를 저장합니다.

**기존에 Supabase를 연결했다면 SQL Editor에서 무엇을 다시 실행하거나 Render 환경 변수를 다시 넣을 필요가 없습니다.** `SUPABASE_URL`, `SUPABASE_SECRET_KEY`는 그대로 사용하세요.

데이터베이스 저장에 성공해야 화면에 '저장됐습니다'라고 표시됩니다. 연결 실패, 글자 수 초과, 존재하지 않는 책 등은 구체적인 오류로 알려줍니다. Supabase 환경 변수가 없으면 기존과 마찬가지로 로컬 파일에 저장되어 Render 무료 서버 재시작 후에는 사라질 수 있습니다.

제한: **방명록 최대 120개**, 각 글/책에 댓글 최대 40개, 모임방 댓글 총 2,400개. 이 제한을 넘으면 기존 기록을 조용히 지우지 않고 저장 오류를 알려줍니다. 닉네임은 계정 인증이 아니므로 이름이 같은 사람을 기술적으로 구별하는 기능은 없습니다. 현재 방명록과 댓글의 개별 수정/삭제 기능은 포함하지 않았습니다.

## GitHub와 Render 배포 순서

1. **GitHub 업로드용 ZIP**을 내려받아 압축을 풉니다.
2. 압축 해제한 파일에서 `server.js`, `pets-server.js`, `package.json`, `public/`, `render.yaml` 등을 **기존 GitHub 저장소 최상위**에 업로드합니다.
3. 기존 파일을 덮어쓰고 **Commit changes**를 누릅니다.
4. Render의 배포 상태가 **Live**가 될 때까지 대시보드에서 확인합니다.
5. 사이트 주소 뒤에 `/health`를 붙여 `"version":"14.27.0"` 및 `"community":"guestbook-comments-v1"`, `"shelfStorage":"supabase"`를 확인합니다.
6. 같은 모임방 코드로 두 사람을 접속시켜 방명록과 책 댓글이 함께 보이는지 검사합니다.

`/health`에 예전 버전이 나온다면 새 `server.js`가 배포되지 않은 것입니다. 브라우저가 예전 화면을 보여주면 강력 새로고침(Ctrl+Shift+R)을 해 보세요. `shelfStorage`가 `ephemeral`이면 Supabase 영구 저장이 연결되지 않은 상태입니다.

### 실행 및 검증

- 의존성 추가 없음, Node.js **18 이상**: `node server.js` 또는 `npm start`
- Node 문법 검사 완료, 실제 WebSocket 참가자 2명으로 방명록·댓글·책 공유 시험 완료.
- 로컬 파일 저장 후 서버 재시작/새 참가자 복원 확인.
- Supabase REST API 모의 서버에 대해 영구 저장 상태 읽기/쓰기 및 실패 시 `STORAGE_FAILED` 확인.
- 실제 브라우저 레이아웃과 입력 UI는 **모의 WebSocket 서버**로 PC 및 모바일에서 확인했습니다. 사용자 Render/Supabase 실제 계정에 직접 접속한 테스트는 아닙니다.
